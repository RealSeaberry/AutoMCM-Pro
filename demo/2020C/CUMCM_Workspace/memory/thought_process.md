# 思维过程记录 — 2020 CUMCM C 题《中小微企业的信贷决策》

## 一、问题类型分析（Checkpoint ① 前置）

### 1.1 题目复述
银行依据信贷政策、交易票据信息与上下游影响力，对中小微企业评估信贷风险，并据此确定
是否放贷、贷款额度（万元）、年利率（4%~15%）、期限（1年）。三个子问题：

- **问题1**：对附件1的 123 家（有信贷记录，含信誉评级 A/B/C/D 与是否违约标签）做信贷风险
  量化分析，给出年度信贷总额**固定**时的信贷策略。
- **问题2**：在问题1基础上，对附件2的 302 家（无信贷记录、无评级、无违约标签）做信贷风险
  量化分析，给出年度信贷总额 **1 亿元**时的信贷策略。
- **问题3**：综合考虑附件2各企业信贷风险 + 突发因素（如新冠疫情）对不同行业/类别企业的
  差异化影响，给出年度信贷总额 1 亿元时的**信贷调整策略**。

### 1.2 问题类型判定
- 问题1 = **评价/分类（监督学习）** + **优化（资金分配）** 混合型：
  - 风险量化：以「是否违约」为监督信号、信誉评级为辅助信号，从发票数据构造特征 → 违约概率
    （PD）模型（逻辑回归为主，随机森林对比）；
  - 信贷策略：给定年度信贷总额固定 → 在 PD、额度上限、利率-流失率权衡下最大化期望收益的
    组合分配问题（背包/组合优化）。
- 问题2 = **迁移打分（无监督标签）** + **约束优化**：
  - 把问题1校准好的特征-风险映射迁移到 302 家无标签企业（同特征空间打分）；
  - 在 1 亿元总额约束下做分配，输出每家企业的放贷额度与利率。
- 问题3 = **情景冲击建模** + **鲁棒/情景调整**：
  - 突发因素对不同类别企业异质性影响：从发票行为画像聚类出"类别"（无法直接用行业字段——
    企业名称已脱敏），参照文献（BIS 2021 分行业信用压力）设定类别冲击系数；
  - 在冲击情景下重估 PD 与期望收益，给出调整策略（收缩高风险类别额度、向抗冲击类别倾斜）。

### 1.3 拟用模型与数学理由
| 子问题 | 模型 | 理由 |
|---|---|---|
| P1 风险量化 | 逻辑回归（L2/L1，概率输出）+ 随机森林对比 | 监督信号明确（违约标签 123 家），LR 可解释、输出天然是 PD；RF 用于验证非线性增益 |
| P1 策略 | 期望收益最大化的组合分配（0-1 背包/贪心+精化） | 总额固定 → 单约束资源分配；目标 = Σ(额度×利率 − 期望损失)，利率受 4%~15% 与流失率约束 |
| P2 风险量化 | 迁移打分：问题1 模型直接预测 + 熵权-TOPSIS 综合评分双轨对照 | 无标签，只能用特征分布相似性迁移；TOPSIS 提供不依赖标签的客观排序交叉验证 |
| P2 策略 | 1 亿元总额下的组合分配（同上目标，加入额度上限分级） | 同 P1 但总额具体化、企业数量 302 家 |
| P3 冲击 | 行业/类别冲击系数（情景法）+ 情景期望收益重分配 | 突发因素无历史数据 → 情景假设 + 文献冲击量级；对脆弱类别加 PD 乘子 |
| 公共 | 客户流失率-利率曲线拟合（附件3，A/B/C 三档） | 决定利率上限的经济权衡：利率越高流失越严重，需平衡单客户收益与客户基数 |

### 1.4 数据规模与处理策略（性能注意）
- 附件1：进项发票 210,948 行、销项发票 162,485 行；附件2：销项 330,836 行、进项 395,176 行。
- 全部特征工程用 pandas 向量化聚合（groupby+agg），禁止逐行 Python 循环。
- 附件2 进项表读到 11 列（后 3 列为空），读取时只取前 8 列。

## 三、§18 可视化惯例调研（画图前先查惯例，记录调研依据）

检索关键词（S3 抽象化，未带题目专有名词）：
- `"credit risk scoring visualization radar chart heatmap convention"` →
  命中 BIS IFC 论文《On measures for illustrating credit risk assessments: the case of
  heat maps, risk matrices and cubes》——**信用风险评估的领域惯例首选热力图/风险矩阵**；
  另命中 FineBI《统计图在金融行业怎么用》——金融风控常用热力图、漏斗图、雷达图。
- `"heatmap risk scoring matrix visualization convention finance"` →
  命中 GRF 会计师事务所《Scoring Risks: Heatmap Development Guide》与 Archer IRM《What do
  Risk Heat Maps Really Tell Us?》——风险评分领域热力图是标准呈现。
- `"stacked bar chart ordered categories ranking visualization best practice"` →
  StackOverflow 讨论"按数值从高到低排序的分组堆叠条形图"——**排序/评价类问题的堆叠条
  形图需按排序维度重排类别顺序**（与 SOP §18 表格一致）。

**结论（决定画什么图）**：本题是评价/分类/排序类问题 → 按 SOP §18 表格与上述检索，
**不使用任何 3D 图**；采用：
1. 特征-风险热力图（企业 × 关键特征，按风险排序重排行序）——信用风险评估领域惯例；
2. 雷达图/堆叠条形图（不同评级/类别企业的特征画像对比，多维度比较惯例）；
3. 按风险排序的堆叠条形图（额度分配结构、金额构成）；
4. 灵敏度分析用 tornado 图（参数影响幅度排序的水平条形图，SOP §18 明确惯例）；
5. 利率-流失率曲线族（附件3，多评级叠画在同一张图）。
以上全部用 `scripts/plot_style.py` 的调色板与 save 规范。

## 五、Los Alamos 触发判定（Director 内联判断）

对照 SOP §9 六条触发源逐条核查：
1. 题目复杂度初判：本题为"提出信贷策略"，含多目标权衡（收益 vs 风险 vs 流失率），但
   属**已定型的金融风控主流范式**（监督 PD 建模 + 约束分配），开放性强弱：中等——不构成
   范式分叉级的复杂度；
2. 用户显式要求多方法比较：无；
3. 文献调研发现 ≥2 种互异范式：有（LR vs 熵权-TOPSIS vs GA-BPNN），但差异在"打分细节"
   而非"问题结构"，且已通过双轨对照（LR 主模型 + TOPSIS 交叉验证）覆盖；
4. 灵敏度分析显示解对假设高度敏感：未知，待 sensitivity 阶段检验（若敏感则补触发）；
5. 题目要求"比较不同方法"：无；
6. 剩余时间预算 >48h：无截止日期信息，且本题数据量大、演示场景时间预算有限。
**裁定：不触发完整 Los Alamos 探索层**，在模型内部做有限范式对照（LR vs RF vs TOPSIS）
以满足"多范式证据"要求；若灵敏度分析暴露高敏感性，再按第 4 条补触发。
